## 0. 项目信息

| 项 | 内容 |
|---|---|
| 产品名称 | BankRiskMonitor（银行客户风险监控工作台）—— v2 升级 |
| Programming Language | Python 3.11 + PySide6 6.11（QtWidgets）+ ECharts（地图）+ SQLite + python-docx；PyInstaller 单文件打包 |
| 项目结构 | `main.py` + `src/{core,gui,providers,report,ai}`，地图资源 `src/assets/china.json + geo/provinces(31) + geo/districts(36)` |
| 现行产物 | `dist/BankRiskMonitor.exe` = **254 MB**（243 MiB） |
| 使用形态 | 银行/担保公司客户经理，单人本地、离线优先 |

**原始需求复述（用户原话归纳）**
1. 软件体积太大，需显著瘦身。
2. 操作页面还需优化（交互/信息架构/易用性）。
3. 需要有稳定产生报告的能力（不能时有时无/崩溃）。
4. 参考一般银行贷后要求，让系统能产出**贷后报告**；没有的信息（如财务数据）做**缺省处理**。

**本次升级的 4 项诉求编号**（全文引用）：①体积瘦身 ②UI 优化 ③稳定报告引擎 ④贷后报告与缺省处理。

## 2. 用户画像与核心场景

**用户画像：客户经理（贷后管理岗）**
- 环境：单人本地 Windows，离线优先；已有 20+ 家企业处于监控中；关注"授信主体 + 关联主体"。
- 手上材料：授信合同/财报/尽调材料（PDF/Word，可上传，系统能提取全文）。
- 诉求：把系统采集的舆情/工商/涉诉/被执行/社媒事件，转成**一份能交上去的贷后检查报告**，缺的地方如实标注"待补充"，而不是编数字。
- 现状痛点：报告入口在工具栏第 7 个按钮；报告只有日报/周报/事件专报，**没有贷后报告**；章节固定，不贴合银行标准；生成偶发失败无提示兜底。

**核心场景（完整动线）**

1. **日常巡检**：打开工作台 → 地图上看高危光点 → 点击光点看该企业舆情 → 右栏事件流联动筛选。
2. **重点核查**：左侧选中企业 → 上传授信材料（合同/财报）→ 触发 AI 影响研判 → 底部摘要出结论。
3. **贷后出报告（本次新增重点）**：选中企业 →（如缺数据，按提示补录/上传材料）→ 点"生成报告" → 选"贷后检查报告"与报告期间 → 系统按银行 8 章**自动组装**：有数据的章节填实，缺数据的章节给出**骨架 + "暂缺，待补充"标注 + 缺省数据说明** → 预览可编辑 → 导出 docx。
4. **批量月报**：勾选多家企业 → 一次生成多份贷后报告（P1）。
5. **异常兜底**：AI 掉线/无网络 → 系统仍能出报告，状态栏明确提示"自动化脚本降级模式"。

## 3. 需求池

> 优先级定义：**P0** Must（本轮必做，不满足即不可交付）／**P1** Should（本轮尽量做）／**P2** Could（可延后）。

### P0（必须）

#### P0-1 打包瘦身至 ≤ 80MB 【关联 ①】
- **需求描述**：
  - **移除 WebEngine 依赖**：地图改用**离线 HTML + 系统原生 WebView** 或**纯 Qt 方案**渲染，剥离 `Qt6WebEngineCore.dll`(195MB) 及 `resources/`(102MB，含 devtools/icudtl.dat)；若无法完全去 WebEngine，则至少剥离 devtools/resources 并压缩。
  - spec `excludes` 排除未用 Qt 子模块：`QtWebEngine*、QtQml/QtQuick/QtQuick3D、QtMultimedia(含 avcodec/avformat)、QtCharts、QtDataVisualization、QtGraphs、QtPdf、QtDesigner、Qt3D*、opengl32sw、qml、translations(仅保留 zh_CN)`。
  - 采用 **onedir + UPX**（单文件会解压到临时目录拖慢启动；onedir 更利于瘦身与冷启动）。
  - 保留地图所需资源：`china.json + geo/provinces(31) + geo/districts(36) + city_centers.json + echarts.min.js`。
- **验收标准**：
  1. 产物为 `dist/BankRiskMonitor/`（onedir）或单文件，总占用 **≤ 80MB**；
  2. 打包内不含 `Qt6WebEngineCore.dll`、`QtWebEngineProcess.exe`、`resources/*.pak`；
  3. 冷启动 ≤ 3s；地图四级下钻、光点落点、点击弹层功能与 v1 一致（回归用例全绿）；
  4. 离线首次运行无缺失 DLL 报错。

#### P0-2 稳定报告引擎（生成必成功）【关联 ③】
- **需求描述**：
  - **章节级容错**：任一章节数据查询/渲染异常不得中断整份报告，异常章节降级为"本节数据获取异常，已跳过并记录日志"，其余章节照常输出。
  - **确定性优先**：默认走**规则引擎**组装正文；AI 仅作增强，AI 超时/失败自动回退规则文本（沿用现有 fallback 并强化为默认路径）。
  - **生成前数据快照与校验**：生成时锁定数据快照（企业/事件/材料），生成过程不受后台刷新影响；生成结束写入**生成日志**（时间、期间、章节、成功/降级/缺省清单）。
  - **强保证**：数据为空（无企业/无事件）也必须产出可打开的 docx（输出"报告期内无监测事件"等标准文案，而非报错）。
  - **失败重试/兜底模板**：docx 写入失败自动重试 1 次；仍失败则输出兜底模板并明确提示用户。
- **验收标准**：
  1. 边界三连测（AI 掉线 / 无事件 / 数据为空）**100% 生成成功**且 docx 可正常打开；
  2. 连续 50 次生成 0 失败；
  3. 单章节人为抛异常，报告仍完整生成，日志含异常章节名；
  4. 每次生成留有一条日志记录，可在报告中心查看。

#### P0-3 贷后检查报告 + 缺省处理 【关联 ④】（本轮核心新增）
- **需求描述**：在报告类型中新增 **"贷后检查报告"**，正文严格按银行通行**8 大章**组织，并将系统数据映射到章节；无法从系统获得的字段一律**缺省处理，不得伪造**。

  **8 章数据映射与缺省规则：**

  | 章 | 章节名 | 系统可提供的数据源 | 缺省/呈现规则 |
  |---|---|---|---|
  | ① | 客户基本情况 | Enterprise（名称/统一社会信用代码/注册地省市区）、工商变更事件 | 名称/地区有值即填；信用代码缺失标"暂缺" |
  | ② | 客户经营管理情况 | 工商变更事件、舆情新闻（经营异常/停业/裁员等） | 有事件即汇总；无则"报告期内未采集到经营异常信息" |
  | ③ | 客户财务状况 | **无财务数据**（或从上传材料提取全文的参考） | **全字段缺省**：输出财务指标对比表骨架，各行填"暂缺，待补充"；页脚注明数据来源缺失 |
  | ④ | 客户所在行业情况 | 无行业库；可由舆情/工商推断行业（参考） | 缺省；如可推断则给"行业（参考）"，景气度/政策影响标"暂缺" |
  | ⑤ | 客户在我行及他行授信情况 | Enterprise.credit_note + 上传授信材料提取文本 | 无材料则整表缺省骨架（授信银行/笔数/余额/品种/担保方式/五级分类/到期日 均"暂缺"） |
  | ⑥ | 客户担保情况 | 上传材料可能含；否则无 | 缺省骨架：保证人/抵质押物/评估价值/抵质押率/价值变动 均"暂缺" |
  | ⑦ | 授信风险分析 | **系统强项**：Event(severity/ai_verdict/relevance) + 关联主体事件 + 穿透图谱 | 按高危/中危事件生成预警信号揭示；无事件则"未发现显著风险信号" |
  | ⑧ | 贷后管理执行情况与结论 | 规则引擎生成：事件统计 + 建议五级分类 + 下一步措施 | 始终生成；含风险等级建议与后续措施（可编辑） |

  **配套表（骨架必出）**：资金流向跟踪表、财务指标对比表（资产负债率/流动比率/速动比率/营收/净利/经营现金流等，含同比列）、担保情况表。

  **缺省处理的三条硬规则**：
  1. **字段级标注**：缺省字段统一填 **"暂缺，待补充"**（表头/结构保留，不留空白歧义）；
  2. **缺省数据说明页脚**：报告末尾固定附"缺省数据说明"小节，列出本次缺省的字段清单及其应来源（如"财务数据需客户经理上传最新财报后补录"）；
  3. **零伪造**：任何缺省字段不得填入估算值/默认值/占位数字，格式使用与真实数据可区分的灰色/斜体标注。
- **验收标准**：
  1. 选择"贷后检查报告"生成的 docx 含**全部 8 章**（无数据章节以骨架 + "暂缺，待补充"呈现，章节齐全率 100%）；
  2. 3 张配套表存在且表头正确；
  3. 末尾含"缺省数据说明"小节，字段清单与实际缺省一致；
  4. 全文字段扫描：无任何伪造数值（抽查 100% 通过）；
  5. 报告期间、编制人、标题、字体（黑体小二/宋体小四/1.5 倍行距）符合既有规范。

#### P0-4 报告入口与生成动线整合 【关联 ②③④】
- **需求描述**：把"生成报告"从工具栏普通按钮升级为清晰的**报告中心**入口：类型含"日报/周报/事件专报/**贷后检查报告**"；选中企业后一键进入；生成前给出缺省预检提示（哪些章将缺省、建议先补录/上传）。
- **验收标准**：核心动线点击步数 ≤ 3；缺省预检提示在生成前可见；生成结果有明确成功/降级反馈。

#### P0-5 主工作台信息架构优化（关键项）【关联 ②】
- **需求描述**：针对现有"三栏 + 底部 AI 摘要 + 顶部工具栏"做**影响面最大**的优化（详见第 4 节线框）：工具栏分组 + 报告中心入口靠前；左栏企业清单增强（搜索/风险徽标/状态）；右栏事件流与预警改为 Tab 合并降噪；底栏摘要可折叠。
- **验收标准**：见第 4 节各条对应验收点；无功能回归。

## 4. UI 设计稿（文字线框）

**现状**：顶部工具栏（8 个平铺按钮）｜左：企业清单（≤340px）｜中：ECharts 地图｜右：事件流 + 预警（上下分栏）｜底：AI 摘要｜状态栏（模型/数据源/模式/倒计时/免责声明）。

**优化目标**：① 报告入口显性化（诉求③④动线）；② 降噪（右栏拥挤）；③ 全局反馈（空/加载态）；④ 不改动核心地图能力。

### 4.1 顶部工具栏（分组 + 报告入口前置）
```
┌ 工具栏 ────────────────────────────────────────────────────────────────┐
│ [监控] 添加企业 | 批量导入 | 刷新监控      [分析] 股权穿透 | 上传材料 | AI研判 │ +右对齐→ 【📄 生成报告 (Primary)】 ⚙设置 │
└────────────────────────────────────────────────────────────────────────┘
```
- 按钮按语义分三组（监控/分析/报告），组间加分隔符；**"生成报告"提级为高亮主按钮**，右对齐常驻。
- 验收：报告入口首屏可见、无需滚动；分组有视觉分隔。

### 4.2 左栏：企业清单
```
┌ 企业清单 ──────────────┐
│ 🔍 搜索企业…            │
│ ───────────────────── │
│ ● 某某科技   [高危] ▸  │  ← 风险徽标(高/中/低/无) + 监控状态点
│ ● 某某置业   [中危] ▸  │
│ ○ 某某贸易   [无]   ▸  │
│ …                      │
│ [全部/高危/中危] 过滤   │
└────────────────────────┘
```

- 新增：搜索框、风险等级徽标、状态点；空态显示"暂无监控企业，点击【添加企业】"。
- 验收：搜索即时过滤；徽标颜色与事件最高严重度一致。

## 5. 待确认问题（≤5，供主理人向用户澄清）

1. **报告主体粒度**：贷后报告的"监测对象"是**单企业一份**，还是需支持"多企业合并一份"？批量场景（P1-4）优先级如何？
2. **财务/授信数据的补录方式**：优先做**手动补录表单**（P1-2）还是先做**从上传材料自动抽取**（P1-3）？是否需要支持导入既有 Excel 财务表？
3. **地图瘦身方案取舍**：是否接受"离线 HTML + 系统原生 WebView（依赖系统 Edge WebView2，Win10+ 一般已内置）"以彻底移除 195MB 内核？还是要求**纯 Qt 自绘**（无外部依赖、但地图交互需重做）？
4. **报告落章口径**：8 章是否**强制全出**（缺省也出骨架），还是允许客户经理**勾选隐藏**某些章？银行内部是否有固定模板文件需严格套用？
5. **是否保留"日报/周报/事件专报"**：v2 是否需与"贷后检查报告"并存，还是以贷后报告为唯一主报告、其余作为轻量快报？
