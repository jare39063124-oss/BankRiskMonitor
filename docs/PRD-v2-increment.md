## 2. 变更点清单

### R1 — 放款前基线 + 放款后差异对比 【P0】

- **需求描述**：为 `Enterprise` 增加「放款日期」并据此建立**放款前基线**。放款日之前该企业的**全部负面信息/状态一律不视为问题，但必须完整留存**（进「基线/历史」视图，可查、可导出）；放款后采集到的信息/状态与基线**逐项对比**，**出现"变更/新增"才视为问题**；沿用放款前状态、无变化的，仅记录、不视为问题。
- **业务规则**（详见 §3）：
  1. **放款前 = 基线（baseline）**：放款日前全部负面信息/状态 → 不参与预警、不计入报告第⑦章显著风险；进「基线/历史」视图，可查、可导出；
  2. **放款后 = 对比期**：逐维与基线对比（法定代表人/注册资本/股东与股权结构/经营范围/经营状态/经营异常/行政处罚/涉诉**新增**/被执行与失信**新增**/税务状态/风险标签），**检出"变更/新增" → 问题**；
  3. 判定结果三态：`change`（放款后变更·问题）/ `baseline`（放款前基线·非问题）/ `undetermined`（无法判定）；
  4. **全量类别统一适用**该口径（舆情、社媒、涉诉、被执行、工商），不再限定工商股权类；
  5. **边界口径**：`变更日期 >= 放款日期` 即视为问题（**变更日与放款日同一天也算**）；
  6. 无放款日 / 无基线 → 无法对比，**按现状披露并显著标注**，**不自动降级为"非问题"**。
- **验收标准**：
  1. 鑫泰/民泰（2026-09-29）、开投（2026-10-10）录入放款日后：放款前信息进「基线/历史」视图且**不进预警**；放款后检出变更的事件**进预警**并计入报告第⑦章；
  2. 对比维度清单（§3.2）每个维度 ≥1 条用例覆盖"变更识别"与"较基线无变化"两种结果；
  3. 判定矩阵（§3.6）全组合各 1 条单测通过；
  4. 无放款日/无基线企业：全量按现状披露且显著标注，**不被自动判为"非问题"**；
  5. 边界用例：变更日期 = 放款日期 → 判为 `change`（问题）。
- **影响范围**：
  - 数据：`enterprise` 新增列 `loan_date`（幂等迁移）；新增**基线补录**列（法定代表人/注册资本/股东/涉诉数/被执行状态等，可空）；新增 `core/baseline_compare.py`（基线构建 + 对比判定，**全系统唯一真源**）；CSV/XLSX 表头新增「放款日期」；
  - 业务逻辑：`ai/rule_engine.assess_by_rule` 可选接收对比结论（仅增强 verdict 文案，不改 severity）；
  - GUI：企业表单（放款日 + 基线补录）、企业清单徽标、事件流「基线/变更」视觉区分、预警筛选、新增「基线/历史」视图；
  - 报告：`report/postloan.py` 第②/⑦章映射 + **报告末尾"基线说明"**。

### R2 — 数据源扩充（仅免费/官方源） 【P0】

- **需求描述**：按 §4 清单补齐「股权变更 / 涉诉 / 被执行 / 行政处罚 / 欠税 / 经营异常」六类覆盖；**本轮只用免费/官方公开源**，付费商业 API 一律降为预留（`enabled:false`，仅在 config 预留 Key 位）。

  4. 每个源遵守 `max_per_host_rps` 限流与 `timeout_seconds`，异常写入日志；

### R5 — 进程残留与单实例 【P0】

- **需求描述**：关闭窗口后进程应完全退出；禁止同时运行两个实例。

## 3. R1 放款前基线 + 放款后差异对比 规格

### 3.1 模型定义

| 概念 | 定义 |
|---|---|
| **放款前 = 基线（baseline）** | 放款日之前该企业的**全部负面信息/状态**，**一律不视为问题，但必须完整留存**：进入「基线/历史」视图（可查、可导出），**不参与预警、不计入报告第⑦章"授信风险分析"的显著风险** |
| **放款后 = 对比期** | 把放款后采集到的信息/状态与放款前基线**逐项对比**，**出现"变更/新增"才视为问题**；沿用放款前状态、无变化的，**只记录、不视为问题** |
| 判定三态 | `change`（放款后变更→问题）/ `baseline`（放款前基线→非问题）/ `undetermined`（无法判定→按现状披露） |
| 判定函数 | `core/baseline_compare.classify(event, enterprise, baseline) -> "change" \| "baseline" \| "undetermined"` —— **全系统唯一真源** |
| 边界 | `变更日期 >= 放款日期` → `change`（**同日也算问题**） |

**单一真源使用方**：事件流渲染标签、预警筛选、企业清单徽标计数、「基线/历史」视图、报告第②/⑦章与报告末尾说明。任何一处不得另写比较逻辑。

### 3.2 对比维度清单（每维度给出"变更识别规则"）

> 记 `loan_date` = 放款日；`change_date` = 该维度最近一次变更日期。**判定一律 `change_date >= loan_date` 才视为问题。**

| 维度 | 变更识别规则（放款后 vs 放款前基线） | 基线可来源（带日期变更记录） |
|---|---|---|
| 法定代表人 | 放款后最新法定代表人 **≠** 基线法定代表人 → 变更 | gsxt 变更记录 / 爱企查变更沿革 |
| 注册资本 | 金额**增减** 或 **增资/减资比例**变化 → 变更 | gsxt / 爱企查 |
| 股东与股权结构 | **新增股东** / **股东退出** / **持股比例变化** → 变更 | gsxt / 爱企查 |
| 经营范围 | 经营范围条目相对基线**发生增减** → 变更 | gsxt / 爱企查 |
| 经营状态 | 存续/在业 **↔** 注销/吊销/迁出 相对基线变化 → 变更 | gsxt |
| 经营异常名录 | 放款后**新列入**经营异常名录 → 变更（新增） | gsxt / 信用中国 |
| 行政处罚 | 放款后**新增**行政处罚记录 → 变更（新增） | gsxt / 信用中国 |
| 涉诉（**新增**） | 相对基线的**增量**（**按新增数量 / 涉案金额 / 案由增量**识别）→ 变更；**存量未了结属基线，不计问题** | 裁判文书网 / 爱企查变更沿革 |
| 被执行与失信（**新增**） | 放款后**新增**执行 / 失信 / 限高记录 → 变更；**存量属基线** | 执行信息公开网 |
| 税务状态 | 新增**欠税** / 被认定**非正常户** / 新增**重大税收违法失信** → 变更 | 信用中国 / 省税务欠税公告 |
| 风险标签变化 | 风险标签集合相对基线**新增**标签 → 变更 | 内部规则引擎（按放款前事件派生基线） |

> **重点口径**：**涉诉、被执行一律按"放款后新增"识别（较基线的增量），不看总量**——放款前已存在的立案/执行未了结属**基线**，不视为问题。

### 3.3 基线从哪里来（优先级与降级链）

按以下**优先级**取用，取到即用；可叠加（高优先级缺失时向下降级）：

| 优先级 | 基线来源 | 说明 |
|---|---|---|
| ① | **数据源返回的变更记录 / 历史沿革（含变更日期）** | 国家企业信用信息公示系统（gsxt）、爱企查等均提供**带日期**的变更记录，可自动构建基线 |
| ② | **用户手动补录的"放款时点状态"** | 法定代表人、注册资本、股东、涉诉数、被执行状态等；企业表单中"基线补录"区（选填） |
| ③ | **放款前已采集的历史事件** | `events` 中 `occurred_at < loan_date` 的记录（已跑批采集的历史数据） |

**降级链**：三者均无 → **降级为"基准缺失"**，报告与界面显著标注 *"基线缺失，无法对比，本期按现状披露"*（见 §3.4、§3.6）。

### 3.4 无放款日期的企业（降级口径）

- 无放款日 → **无法建立基线** → 明确降级口径：**全部按现状披露**，并在界面与报告**显著标注** *"未设放款日，无法做放款前后对比"*；
- **不自动降级为"非问题"**（这些事件仍完整展示、进入"待核实·按现状披露"清单，需人工复核）；
- 一旦补录放款日，重新构建基线并重跑判定。

### 3.5 边界口径（用户已拍板）

| 情形 | 判定 |
|---|---|
| `change_date > loan_date` | `change`（放款后变更 → 问题） |
| **`change_date == loan_date`** | **`change`（同日也算问题）** —— 对比期判定用 **`变更日期 >= 放款日期`** |
| `change_date < loan_date` | `baseline`（放款前基线 → 非问题） |
| 任一日期缺失/非法 | `undetermined`（无法判定 → 按现状披露） |

> **本条替换原 v2-increment 中"`occ == loan_date` 视为放款前"的规定**：同日一律计入对比期，视为问题。

### 3.6 判定矩阵（维度：是否已设放款日 × 是否有基线 × 是否检出变更）

| # | 已设放款日 | 有基线 | 检出变更 | 判定 | 信息流 | 预警 | 报告第⑦章 | 报告末尾说明 |
|---|---|---|---|---|---|---|---|---|
| N1 | 是 | 有 | **是**（`change_date >= loan_date`） | **change 放款后变更 = 问题** | 正常高亮，标签「放款后·变更」 | **进入**（沿用原 severity） | **计入**显著风险信号 | 注明对比期区间 |
| N2 | 是 | 有 | 否（无变化/沿用基线） | **baseline 放款前基线 = 非问题** | 灰显降饱和，标签「放款前·基线」，进「基线/历史」视图 | **不进入** | **不计入** | 注明基线来源与对比期区间 |
| N3 | 是 | **无** | —（无法对比） | **undetermined 无法对比** | 正常呈现，标签「基线缺失·无法对比」 | **不进入预警**，改入「待核实·按现状披露」清单 | 不计入显著风险，单列"无法对比项" | **显著标注**"基线缺失，无法对比，本期按现状披露" |
| N4 | **否** | 无 | —（无放款日） | **undetermined 无法判定** | 正常呈现，标签「未设放款日·无法对比」 | **不进入预警**，改入「待核实·按现状披露」清单 | 不计入显著风险，单列"无法对比项" | **显著标注**"未设放款日，无法做放款前后对比" |

> 关键不变量：**预警区只显示 N1（放款后·变更）**；N2 完整留存但一律不视为问题；N3/N4 **不自动降级为"非问题"**，而是显著标注、转人工复核。

### 3.7 四处表现对照（信息流 / 预警 / 报告第⑦章 / 报告末尾说明）

| 处 | 放款前·基线（N2） | 放款后·变更（N1） | 无法判定（N3/N4） |
|---|---|---|---|
| **信息流** | 灰字/降饱和，标签「放款前·基线」，归入「基线/历史」视图（可查、可导出） | 正常高亮，标签「放款后·变更」 | 正常行，标签「基线缺失·无法对比」/「未设放款日·无法对比」 |
| **预警** | **不进入**（放款前信息一律不视为问题） | **进入** | **不进入预警**，改入「待核实·按现状披露」清单 |
| **报告第⑦章（授信风险分析）** | **不计入**显著风险 | **计入**显著风险信号 | 不计入显著风险；另列"无法对比项" |
| **报告末尾说明** | 注明基线来源与对比期区间 | 注明对比期区间 | **显著标注**"基线缺失/未设放款日，无法做放款前后对比，本期按现状披露" |

### 3.8 数据与实现要点

- **迁移**：`init_db()` 内追加幂等列迁移（先 `PRAGMA table_info(enterprise)` 查缺列，缺则 `ALTER TABLE enterprise ADD COLUMN loan_date TEXT DEFAULT ''`；基线补录列同理，均可空）；老库零破坏。
- **不新增 event 列**：对比判定在读取层派生（`loan_phase` / `compare_result`），不改 `event` 表结构、不污染既有 `severity` 字段——保证可回退、可单测。
- **判定单一真源**：新增 `core/baseline_compare.py`，暴露 `build_baseline(ent) -> Baseline | None` 与 `classify(event, ent, baseline) -> "change" | "baseline" | "undetermined"`；所有展示/筛选/报告统一调用。
- **企业表单**：`EnterpriseDialog` 新增「放款日期」`QLineEdit`（占位 `YYYY-MM-DD`，选填）+ 轻量格式校验（非空时必须匹配 `\d{4}-\d{2}-\d{2}`）；新增「基线补录」折叠区（法定代表人/注册资本/股东/涉诉数/被执行状态，选填）。
- **导入导出**：`sync.CSV_HEADERS` 增「放款日期」，CSV/XLSX 导入导出同步支持。
- **边界与兜底**：`change_date`/`occurred_at` 非法格式 → 按 `undetermined` 处理；`loan_date` 非法 → 视为未设置并提示。

```
└───────────────────────────────────────────────────────────────────────┘
```

### 6.2 左侧企业清单：点击联动（本次核心）

| 需求点 | 交互规格 |
|---|---|
| **选中态** | 选中项加背景高亮 + 左侧 3px 主题色（`PRIMARY=#00FF9C`）竖条；`QListWidget` 默认选中态增强 |
| **筛选联动** | 点击企业 → 右侧事件流**即时**仅显示该企业事件；预警 Tab 同步过滤；顶部显示标签「企业筛选：鑫泰地产 [×]」 |
| **筛选范围** | 默认 = 该企业 + 其**股权穿透关联主体**事件（用户已确认包含）；关联主体行缩进 `└` 并加「关联」标签区分主/关联 |
| **一键清除** | 标签旁 `[×]` 或独立「清除筛选」按钮；清除后恢复全部事件 |
| **事件数徽标** | 每条显示 `[高N]` 徽标，颜色随最高风险等级（红/橙/黄/绿）；数据来自按企业聚合的事件统计（仅计"放款后·变更"为风险，基线不计入风险数） |
| **风险色标** | 名称前圆点：`●高(红) ●中(橙) ●低(黄) ○无(绿)`，与事件最高 severity 一致 |
| **排序** | 下拉「排序：风险等级▼ / 名称 / 事件数」，默认按风险等级高→低 |
| **过滤** | 下拉「全部 / 高危 / 中危 / 无事件」 |
| **空态** | "暂无监控企业，点击工具栏「添加企业」" |
| **保留** | 右键菜单（编辑/股权穿透/停止监控）不变 |

### 6.3 其余区域变更要点（承接既有 v2 设计）

- **顶部工具栏**：按「监控 / 分析 / 报告」三组加分隔符；「生成报告」提级为高亮主按钮靠右常驻。
- **右栏**：`事件流 / 预警` 由上下分栏改 **Tab**；预警 Tab 标题带角标 `(高危+中危数)`；切换保留各自筛选状态。
- **信息流**：由表格改为**卡片式行**（首行=时间+类型+严重度色标，次行=标题+来源），**双击展开详情**（R3）；**两种视觉区分**：「放款前·基线」灰显降饱和、「放款后·变更」正常高亮；**预警区只显示"放款后·变更"**。
- **底部 AI 摘要**：支持折叠/展开。
- **空态/加载态**：地图"地图加载中…"、事件流"当前筛选无事件，试试放宽筛选条件"、报告"正在生成 docx…"。

### 6.4 验收要点（对应 §1 G4）

选中态可辨识｜点击即筛选（含关联主体）｜一键清除｜事件数徽标｜风险色标｜按风险等级排序｜过滤下拉｜**基线/变更视觉区分**｜**预警区仅显示放款后变更**｜空态文案｜右键菜单与地图联动无回归。
