# BankRiskMonitor

银行管户企业风险监控工具（Python + PySide6 桌面应用）。

面向银行贷后管理场景：对管户企业的**舆情、工商变更、涉诉、被执行/查封**四类公开信息进行自动化采集，支持**股权上下穿透 1-2 层**发现关联企业风险，并通过 **AI Agent（OpenRouter 免费模型）** 对每条风险事件做情绪/严重度/相关性研判与授信影响分析；AI 不可用时自动降级为**本地规则研判引擎**，保证监控不中断。

> 仅采集公开渠道信息用于银行内部贷后管理，不向客户发送任何信息。详见文末免责声明。

## 功能列表

- **管户企业管理**：添加/删除监测对象，集中展示风险概览与地域地图分布（ECharts 中国地图，按严重度/信息类型着色）。
- **五类风险信息采集**（声明式数据源，可增删/启停/排序，无需改代码）：
  - 舆情：百度新闻、RSSHub、澎湃热榜等
  - 工商变更：爱企查、国家企业信用信息公示系统（gsxt）、商业 API
  - 涉诉：裁判文书网
  - 被执行/查封：全国法院执行信息公开网（zxgk）
  - 社媒：微信公众号（搜狗微信）、微博、抖音、快手、小红书（详见下文“社媒信息采集”）
- **股权穿透**：向上股东、向下对外投资各穿透 1-2 层（`config.yaml` 可调），把关联企业风险纳入监测。
- **AI Agent 研判（5 角色）**：事件研判（情绪/严重度/相关性/一句话结论）、批量研判、授信影响分析、监测报告文本生成、穿透关系分析。
- **免费模型 fallback**：`model_policy.yaml` 声明 OpenRouter 免费模型（cost==0）的尝试顺序，禁止元路由（如 `openrouter/auto`）。
- **自动降级与补跑**：OpenRouter 无响应/连续失败达阈值时自动切换本地规则引擎（词库打分 + 来源可信度加权），降级结果统一标注 `pending_review` 并加降级前缀；任务在队列中积累，AI 恢复后自动补跑。
- **监测报告导出**：一键生成行内格式 Word 报告（黑体标题、宋体正文、1.5 倍行距、自动章节编号）。
- **限流与代理**：每主机每秒请求数限制、自定义 User-Agent、可配 HTTP 代理。
- **设置中心**：工具栏/状态栏“设置”入口，六页签集中管理显示显隐、刷新频率、监控参数、数据源、AI 与报告设置（详见下文“设置中心”）。
- **免安装便携 + 配置自举**：打包后单个 exe，双击即可运行；首次启动自动在 exe 同目录补齐 `config.yaml` / `model_policy.yaml` / `.env` 与 `data\` 数据目录，已有配置文件不会被覆盖（详见下文“配置自举”）。

## 使用说明

### 开发运行

```bash
pip install -r requirements.txt
python main.py
```

要求 Python 3.11+。开发模式下配置文件与 `data/` 目录均位于项目根目录。

### 打包

```bat
build_exe.bat
```

产物为 `dist\BankRiskMonitor.exe`（onefile 模式）。如 onefile 因 QtWebEngine 报错，可编辑脚本将 `--onefile` 改为 `--onedir`。

### 打包运行（免安装交付）

将 `BankRiskMonitor.exe` 单独放到任意目录，**双击即可运行**——首次启动会自动在 exe 同目录生成：

```
BankRiskMonitor.exe
config.yaml          # 自动生成，内置默认数据源配置
model_policy.yaml    # 自动生成，内置免费模型策略
.env                 # 自动生成，空模板（OPENROUTER_API_KEY=），需要 AI 时自行填入 key
data\                # 自动生成，SQLite 数据库 data\monitor.db
```

三个配置文件**只在缺失时生成**；目录中已存在的配置不会被读取后覆盖、也不会被追加修改，可放心在正式环境沿用既有配置。

## 社媒信息采集（五渠道）

在舆情/工商/涉诉/被执行之外，应用新增**社媒**信息域，覆盖五个渠道：

| 渠道 | config.yaml 源名 | 说明 |
|------|------------------|------|
| 微信公众号 | `wechat_sogou` | 经搜狗微信搜索检索公众号文章 |
| 微博 | `weibo` | 微博公开搜索结果 |
| 抖音 | `douyin` | 抖音公开搜索结果 |
| 快手 | `kuaishou` | 快手公开搜索结果 |
| 小红书 | `xiaohongshu` | 小红书公开笔记搜索 |

- **Cookie 提升抓取成功率**：五个渠道均支持在 `config.yaml` 的 `sources.social` 对应源 `params.cookie` 中粘贴浏览器 Cookie（登录后从开发者工具复制整串 Cookie 头即可）。未登录状态下各渠道可见内容有限，粘贴 Cookie 后可显著提高抓取成功率与覆盖面。
- **反爬自动 fallback**：社媒站点反爬较强，Provider 会识别验证码/登录墙/空壳页等反爬特征；某渠道被拦截或请求失败时自动跳过该源并记录日志，**不影响其他渠道与其他信息域的正常采集**。
- 各源可独立启停、排序（`enabled` 开关 + Provider 链顺序），也可在“设置中心 → 频率设置”中整体控制社媒域的启停与执行频率。

## 配置自举（裸 exe 双击即用）

上一版本裸 exe 双击会因缺少 `config.yaml` 启动崩溃，现已修复：启动时执行**配置自举**（`ensure_boot_files()`），自动补齐 exe 同目录缺失的三个引导文件：

- `config.yaml` / `model_policy.yaml`：缺失时写入与仓库一致的内置默认内容（UTF-8）。
- `.env`：缺失时只写**空模板** `OPENROUTER_API_KEY=`，**绝不包含任何真实密钥**；已存在则完全不动。
- 单个文件写入失败（如目录只读）时跳过该文件，保证启动流程永不因此中断。

因此最简交付方式为：只发一个 `BankRiskMonitor.exe`，用户双击后自动完成所有初始化。

## 设置中心

主界面**工具栏**与**状态栏右侧**均有“设置”按钮，打开设置中心（六页签，保存后即时生效）：

- **显示设置**：逐项显隐中央地图、企业清单、事件流、预警列表、AI 研判摘要、状态栏刷新倒计时六个界面元素；关闭的元素从布局移除，重新勾选即恢复。
- **频率设置**：
  - 全局刷新周期（分钟，0 = 关闭自动刷新）；
  - 五类信息域（舆情/工商变更/涉诉/被执行/社媒）独立启停与执行倍率（0.5x = 每两次全局刷新执行一次，1x/2x = 每轮均执行）；
  - 网络超时（秒）。
  禁用的信息域刷新时直接跳过，不产生网络请求。
- **监控设置**：定时刷新周期、HTTP 代理、股权穿透上/下穿层数。
- **数据源设置**：各信息域数据源勾选启停、上下移调整优先级。
- **AI 设置**：模型策略、fallback 顺序等 AI 相关参数。
- **报告设置**：监测报告导出相关参数。


## 配置说明

### config.yaml

- `app`：应用名称、自动刷新周期（分钟）、HTTP 代理。
- `penetration`：股权穿透开关与上下穿透层数（1-2）。
- `sources`：**声明式数据源登记**。每类信息（news / biz_change / lawsuit / enforcement / social）是一个有序 Provider 链，排在前面的优先；`enabled` 控制启停；`params` 中的 key 留空表示该源未启用（自动跳过）。新增数据源只需登记一行，无需改代码。
- `network`：超时、限流、User-Agent。

### model_policy.yaml

- `policy`：仅允许免费模型（`require_cost_zero: true`），封禁 `openrouter/auto` 等元路由。
- `fallback_models`：OpenRouter 免费模型 fallback 列表，按序尝试。
- `request`：超时、重试、退避与降级阈值（连续失败 N 次进入降级模式）。

### .env

存放 OpenRouter API Key（用于 AI 研判）：

```
OPENROUTER_API_KEY=你的key
```

`.env` 已被 `.gitignore` 排除，不会进入版本库。

## 国内网络说明

- **OpenRouter 直连可能无响应**：此时应用自动降级为本地自动化规则脚本研判（结果标注 `engine=rule`、`pending_review=1`，文本带降级前缀），采集与监控流程不受影响；AI 恢复后队列自动补跑。
- 可在 `config.yaml` 的 `app.proxy` 配置 HTTP 代理（如 `http://127.0.0.1:7890`）改善 OpenRouter 连通性。
- 部分公开数据源（gsxt、裁判文书网等）反爬较强，采集失败会记录日志并跳过，不影响其他数据源。
